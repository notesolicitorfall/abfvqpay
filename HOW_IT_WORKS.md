# Как работает информационная система

## Технологии

- **Python** — язык, на котором написана логика приложения.
- **Tkinter и ttk** — стандартные средства Python для создания окон, меню, таблиц и форм. Интерфейс открывается как отдельное настольное приложение.
- **SQLite** — встроенная файловая база данных. Она хранится в `internet_provider.db`; отдельный сервер базы данных не требуется.
- **PyCharm** — среда разработки, из которой удобно запускать программу и работать с файлами проекта.

Для обычного запуска браузер, веб-сайт и веб-сервер не используются. Сторонние Python-библиотеки приложению не нужны; в установленном Python должен быть доступен Tkinter.

## Запуск и подготовка данных

1. В PyCharm откройте `app.py` и нажмите **Run**. Альтернативно запустите в терминале проекта `.\.venv\Scripts\python.exe app.py`.
2. `app.py` вызывает функцию запуска из `desktop.py`.
3. До показа окна приложение проверяет и создаёт структуру SQLite-базы.
4. Если база ещё не содержит клиентов, она заполняется демонстрационными данными.
5. Появляется окно входа. Сотрудник входит по логину и паролю либо создаёт аккаунт.
6. После входа открывается главное окно. Закрытие окна завершает приложение; база остаётся на диске.

Пароль не хранится в базе в открытом виде: сохраняются соль и криптографический хеш PBKDF2-HMAC-SHA256. При проверке пароля приложение заново вычисляет хеш и сравнивает его с сохранённым.

При первом запуске обновлённой версии существующие записи сохраняются и после регистрации первого сотрудника закрепляются за его аккаунтом. Последующие новые аккаунты начинают с собственных пустых разделов.

## Что показывает система

В меню доступны обзор, статистика и восемь разделов из ER-модели:

1. **Клиенты** — контакты, дата регистрации и состояние обслуживания.
2. **Договоры** — номер договора, клиент, тариф, адрес подключения и даты действия.
3. **Тарифы** — название, скорость, цена, описание и статус.
4. **Адреса** — город, улица, дом и квартира.
5. **Оборудование** — клиент, MAC-адрес, тип, модель и статус устройства.
6. **IP-адреса** — IP, тип, адрес подключения и статус назначения.
7. **Платежи** — договор, сумма, дата, способ оплаты и статус платежа.
8. **Заявки** — клиент, договор, тема, описание, статус и даты обращения.

Сводный экран рассчитывает количество записей текущего сотрудника, активные договоры, сумму его оплаченных платежей за текущий месяц и число незакрытых заявок. Там же отображаются последние платежи и обращения.

В разделе **Статистика** можно переключить диаграмму между неделей, месяцем и годом. Она показывает количество договоров, заключённых вошедшим сотрудником, по дням, неделям или месяцам выбранного периода. Учитывается дата начала договора. В договоре сотрудник указывается автоматически по вошедшему аккаунту; поле доступно для просмотра при создании и редактировании.

## Как выполняются операции

- При открытии раздела приложение загружает из SQLite только строки, принадлежащие вошедшему сотруднику, и показывает их в таблице окна.
- Поиск фильтрует уже загруженные строки по введённому тексту.
- При создании или изменении записи открывается форма с полями этой сущности. Для связей — например, клиента в договоре — можно выбрать существующую запись из выпадающего списка.
- После нажатия **Сохранить** данные записываются в SQLite. Таблица раздела перечитывается, чтобы отобразить результат.
- Удаление выполняется после подтверждения. Ограничения внешних ключей защищают связанные записи: например, нельзя удалить клиента или договор, пока существуют записи, которые на них ссылаются.
- База также проверяет уникальность номеров договоров, MAC- и IP-адресов, а для скорости и сумм применяются ограничения допустимых значений. Если проверка не пройдена, интерфейс показывает сообщение вместо молчаливого удаления или сохранения.

## Структура данных

`app.py` хранит описание сущностей и их полей, а также SQL-структуру таблиц и связи между ними. Связанные таблицы используют идентификаторы: договор ссылается на клиента, тариф и адрес; платёж — на договор; устройство — на клиента; IP-адрес — на адрес подключения; заявка — на клиента и, при необходимости, на договор.

У каждой записи есть владелец-сотрудник; списки связанных клиентов, тарифов, договоров и адресов также ограничены текущим аккаунтом. В договоре дополнительно сохраняется идентификатор сотрудника, заключившего его, и именно эти договоры учитываются в личной статистике.

Файл `internet_provider.db` содержит аккаунты и фактические данные. Не удаляйте его, если нужно сохранить внесённые записи. Удаление этого файла при закрытом приложении приведёт к созданию новой базы с демонстрационными данными при следующем запуске.
